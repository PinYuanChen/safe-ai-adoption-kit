測試地圖與待辦

一句話：每個測試都是一個保全，各自顧一扇門。這張地圖記錄哪扇門有人顧、哪扇還空著。

背景

測試越寫越多，容易忘記某個測試當初是在防什麼。改程式時看到它紅了，要知道是哪個承諾被打破。

觀念

元件地圖：誰寫的、住哪裡

每個保全顧哪扇門

測試保護的承諾它紅了代表
直接回答不需要工具時，一輪就收工loop 多跑了，或取文字取錯
跑工具再回答tool_use → run_tool → tool_result 接對 id → 最終答案messages 組錯，或 id 對不上
一直呼叫工具跑滿 MAX_TURNS 會停保險絲壞了，可能無限燒錢
max_tokens / refusal沒拿到完整答案就明確失敗在假裝成功
未知的 tool回 is_error 給模型，不當掉模型亂點菜時 agent 會翻桌
缺參數 / 型別錯誤回 is_error，不 KeyError同上
未知的 tool，沒帶 order_id訊息說的是模型叫的 tool又變成先驗參數、再認 tool
工具當掉回 is_error，agent 不當掉try / except 不見了
工具當掉不外洩exception 的內容不進 tool_result內部細節又送給模型了
多個文字區塊用 \n 依序接起來只取了第一段
工具前的開場白不混進答案，但保留在對話紀錄使用者看到「Let me check」黏在答案上
end_turn 沒有文字 / 只有空白raise，不回傳一片空白使用者又會收到空白回答
CLI（3 個）答案在 stdout、trace 在 stderr、失敗時 exit 1輸出混在一起，或失敗還回報成功

已決定

end_turn 卻一個字都沒說，該怎麼辦？
比照 max_tokens：拿不到答案就 raise，不要假裝成功。上表和測試都更新了，經過見 0014。
