dict、list，以及「點」和「中括號」之爭

一句話：模型回給你的是物件，用 .；你送給模型的是 dict，用 ["key"]。搞反了，Python 會用紅字罵你。

背景

agent loop 裡同時有兩種長得很像的東西在飛：SDK 回傳的 response（物件），跟你自己組的 messages（dict）。它們都裝著 type、content 之類的欄位，但取值方式不一樣。

觀念

list 和 dict：俄羅斯娃娃

從 JSON 讀進來的東西只有兩種積木：list（排好隊的一串，用數字取）和 dict（有名牌的抽屜，用名字取）。它們可以無限套娃：

點 vs 中括號

東西是什麼怎麼取
response、blockSDK 物件（測試裡是 FakeMessage）response.stop_reason、block.text
messages 裡的每則訊息你自己組的 dictmsg["role"]
run_tool 的回傳值dictresult["is_error"]
block.input物件的屬性，但值本身是 dictblock.input["order_id"]（點完再中括號）

[] 跟 .get() 的性格差異

block.input["order_id"]       # 沒這個 key → KeyError，整個程式翻桌
block.input.get("order_id")   # 沒這個 key → 默默給你 None，讓你自己處理

資料來自外面、不能保證格式時（例如模型送來的 tool input），用 .get() 比較有禮貌。

踩雷紀錄

AttributeError: 'dict' object has no attribute 'role'
對 dict 用了點。改成 msg["role"]。
TypeError: 'TextBlock' object is not subscriptable
對物件用了中括號。改成 block.text。
