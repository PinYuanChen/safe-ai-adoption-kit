FakeClient：你是導演，它是照劇本念台詞的演員

一句話：FakeClient 不會思考，只會照順序吐出你排好的 FakeMessage。所以測的不是模型聰不聰明，而是你的迴圈反應對不對。

背景

測試裡 reply、FakeMessage、FakeClient、text_response() 全擠在一起，分不清誰包誰、誰傳給誰。

觀念

演員表

名字是什麼劇組角色
reply測試裡自己取的變數，就是個字串標準答案
FakeMessage假的模型回覆，結構跟真的 response 一樣（見 0008）劇本上的一句台詞
text_response() / tool_use_response()快速做出 FakeMessage 的小工具台詞範本
FakeClient裝著一串 FakeMessage 的排隊機照劇本念台詞的演員
client.calls每次 create() 收到的參數片場的錄影機

一場戲怎麼演

演員的內部構造

FakeClient
├── _responses   還沒念的台詞，每次 create() 從最前面拿一句
├── calls        錄影機：每次 create() 收到什麼都 deep copy 存下來
├── remaining    還剩幾句
└── messages
    └── create(**kwargs)
        1. 錄影：kwargs 深複製一份放進 calls
        2. 台詞念完了？→ raise FakeClientExhausted
        3. 拿出下一句；如果是 exception 就丟出去（模擬 API 掛掉）
        4. 否則回傳那個 FakeMessage

為什麼是 client.messages.create 兩層？因為真的 SDK 就長這樣。假演員要穿得跟真演員一模一樣，run_agent 才不用為了測試改寫法。

兩個方向的檢查

不需要演員的時候

只想測 run_tool？不用請演員，自己做一張點菜單丟進去就好：

block = ToolUseBlock(id="toolu_1", name="lookup_order", input={})
result = run_tool(block, orders)

踩雷紀錄

FakeClientExhausted
演員台詞念完了，你的迴圈還在 call。代表迴圈沒在該停的時候停，或劇本少排了一句。
