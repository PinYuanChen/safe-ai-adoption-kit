Agent loop：一場你來我往的對話

一句話：模型不會自己執行工具。它只會「點餐」，說「請幫我呼叫 lookup_order，參數是 HL-10421」。真正下廚的是你的 run_tool。

背景

「Agent 會用工具」聽起來很像模型自己伸手去查資料庫。其實它被關在 API 的另一頭，什麼都碰不到。它能做的只有開一張點菜單，然後等你把菜端回去。

觀念

餐廳比喻

餐廳Agent loop
客人使用者
只會看菜單、開單的服務生模型
菜單LOOKUP_ORDER_TOOL（tool 定義）
點菜單tool_use 區塊
廚房run_tool → lookup_order
端回去的菜tool_result
領班（決定什麼時候該收工）run_agent 的迴圈

一輪完整的流程

client 可以換人

run_agent(question, client, orders) 根本不在乎 client 是誰，只要它有 client.messages.create(...) 就好：

  • 真的 anthropic.Anthropic()：只有你自己用 scripts/with-secrets.sh 跑，會花錢。
  • FakeClient：所有測試用它，免費、可預測、一秒跑完（見 0009）。

這種「只要長得像就能用」的設計叫 duck typing：走路像鴨子、叫聲像鴨子，Python 就當它是鴨子。

踩雷紀錄

為什麼要有 MAX_TURNS？
如果模型一直點菜、永遠不說「好了」，沒有上限的迴圈會一直燒 token。這也是 Component 3 要測的「runaway loop」。
