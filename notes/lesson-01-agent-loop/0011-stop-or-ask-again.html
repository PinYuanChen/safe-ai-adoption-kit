該停下來，還是該再問模型一次？

一句話：手上有模型不知道的新資訊，再問一次才有意義。沒有新資訊，再問只是花錢聽同一句話，除非你改了請求本身（見踩雷紀錄的更正）。

背景

寫「不存在的 tool」測試時卡住了：為什麼 client.calls 是 2 次？我一開始以為這兩次是「create 一次，加上 assistant 去查訂單一次」。接著又想不通：那 max_tokens 和 refusal 的測試為什麼只有 1 次？

觀念

client.calls 只數「問模型」的次數

執行 tool 是我自己的 Python 函式，跟模型無關，不會被記進 client.calls。兩次都是 create，第二次是為了讓模型讀到結果。

情況有新資訊嗎再問會改變結果嗎做法
refusal沒有不會raise，停下來
max_tokens（已更正）沒有，但請求可以改調高 max_tokens 就可能會丟掉回應，調高重送一次；再截斷才 raise
不存在的 tool、參數錯誤有：錯誤結果會回報給模型，繼續

白名單 vs 黑名單

if response.stop_reason == "end_turn":
    ...                     # 允許的第 1 種
elif response.stop_reason == "tool_use":
    ...                     # 允許的第 2 種
else:
    raise AgentLoopError(f"stop_reason: {response.stop_reason} ...")   # 其他全擋
寫法邏輯遇到沒想到的值
黑名單列出不允許的值放行，繼續跑
白名單列出允許的值，其他全擋擋下來

我不可能預先想到所有壞情況，所以不確定的時候就停下來。這叫 fail closed，這個 repo 的 Bash guard 用的也是同一個原則。

踩雷紀錄

更正（2026-11-05）：max_tokens 不是「再問也沒用」
這篇原本把 max_tokens 和 refusal 放在一起，說再問不會改變結果。同樣的請求再送一次確實沒用，但回答是被我設的上限截斷的，調高就可能成功。驗收時才抓到，細節見 0015。
只擋了 max_tokens，其他照樣 runaway
第一版只寫了 if response.stop_reason == "max_tokens"，測試全綠。換成測試沒涵蓋的值，同樣的請求被送了 5 次： 
refusal       -> unexpected stop_reason: exceed max turns on turn 5 | create() calls: 5
pause_turn    -> unexpected stop_reason: exceed max turns on turn 5 | create() calls: 5
stop_sequence -> unexpected stop_reason: exceed max turns on turn 5 | create() calls: 5
模型第一次就拒絕了，我卻看到「超過回合上限」。加上 else 之後，每一種都在第 1 次就停。
IndexError 不是 calls[1] 的錯
client.calls[1]["messages"][2]["content"][0] 有四個中括號，錯誤訊息不會說是哪一個。我以為是 calls[1]，其實上一行 len(client.calls) == 2 已經通過了，真正出錯的是最後的 [0]：content 是空的 list，因為迴圈把 cancel_order 默默跳過了。
怎麼抓是哪一個中括號
在那行前面暫時加 print(client.calls[1]["messages"][2])，跑 uv run pytest -s，-s 會讓 print 顯示出來。確認完記得刪掉。
錯誤訊息要說真正的原因
我原本打算讓其他 stop_reason 也回報「超過 max turns」。但 max_tokens 是回答被截斷，要調的是 max_tokens，跟回合數無關。訊息說錯原因，就會去修錯地方。
