pytest 生存指南

一句話：函式名字用 test_ 開頭，裡面寫 assert，pytest 就會自動找到它、跑它、幫你計分。

背景

遇過兩個謎團：參數寫個 orders，資料就自己出現了？還有，為什麼明明有好幾個測試，一個錯誤就讓全部停擺？

觀念

pytest 的一天

fixture：自動送到的便當

# tests/conftest.py
@pytest.fixture
def orders(orders_data):
    return orders_data["orders"]

# tests/test_tools.py
def test_finds_a_shipped_order(orders):      # ← 參數名叫 orders
    result = lookup_order("HL-10421", orders)
    assert result["status"] == "shipped"

pytest 看到參數叫 orders，就去 conftest.py 找同名的 fixture，做好之後送過來。名字對上就是唯一的規則。

另外 conftest 裡有一個 autouse=True 的 fixture，每個測試都會自動套用：它清掉 API key 環境變數，避免真的 client 意外連上 API 燒錢。

測「應該要出錯」

with pytest.raises(AgentLoopError, match="max turns"):
    run_agent("...", client, orders)

意思是：with 區塊裡一定要丟出 AgentLoopError，而且訊息要包含 "max turns"。沒丟，或丟錯種類，測試就失敗。

常用選項

選項作用什麼時候用
-v列出每個測試的結果想看清楚哪個過、哪個沒過
-x第一個失敗就停一次只想專心修一個問題
--maxfail=3失敗 3 個就停介於兩者之間
--continue-on-collection-errors有檔案 import 失敗，其他照跑想先看其他測試的狀況

先紅後綠

為什麼要先看它失敗？因為一個「怎樣都會過」的測試比沒有測試更糟：它會讓你以為安全。
