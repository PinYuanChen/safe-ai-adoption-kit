出錯的時候：raise 還是回傳錯誤？

一句話：錯誤要交給模型讀的，就回傳錯誤 dict；錯誤要讓呼叫你的人知道的，就 raise。

背景

查不到訂單、模型傳錯參數、模型講到一半被截斷，這些都是「出錯」。但它們該由不同的人來處理。

觀念

誰該收到這個壞消息？

為什麼查不到訂單不 raise？因為「查不到」是正常、可以預期的答案，就像店員說「這個型號沒貨」。你不會因此把店燒了。把它好好包成 dict 交給模型，模型就能跟使用者說「查不到這筆訂單」，而不是自己編一個。

None：「這裡什麼都沒有」

order_id = block.input.get("order_id")   # 沒這個 key → None
if order_id is None:                     # 跟 None 比較用 is，不用 ==
    ...

為什麼不回傳 None 表示查不到？因為模型看到一片空白，分不出是「沒這筆訂單」、「系統壞了」還是「還沒查」。分不出來的時候，模型常會自由發揮。

isinstance：驗明正身

isinstance(order_id, str)    # 是字串嗎？ True / False
type(order_id).__name__      # 它到底是什麼？ 例如 "int"

還記得型別標註只是備忘錄嗎（見 0003）？模型可能傳 10421 而不是 "HL-10421"，Python 不會幫你擋，要自己檢查。

自訂錯誤

class AgentLoopError(Exception):
    """Raised when the agent loop cannot finish normally."""

raise AgentLoopError("stop_reason: max_tokens on turn 1")

自己取一個錯誤名字的好處：呼叫的人可以只接這一種錯誤，測試也能精準檢查（見 0005 的 pytest.raises）。

踩雷紀錄

KeyError: 'order_id'
run_tool 原本寫 block.input["order_id"]，模型一忘了傳參數，整個 agent 就翻桌。改用 .get() 加檢查，回傳 is_error。
錯誤訊息寫給誰看？
寫給模型看：要具體說出「缺了什麼、應該是什麼型別」，它下一輪才知道怎麼改。
